# Tech design — magpie-lite

Source PRD: `magpie-lite-PRD.md` (df7e0fb). Grounding: `grounding.md` (R/C/T IDs). Frontier: `frontier.md` (B IDs). Priority: F-04 allowance and F-03 switching are core; F-01/F-02 serve them; F-07/F-08 are secondary.

## 1. Architecture  (DEC-02 · DEC-08 · ADR-0003)

One macOS app process, menubar-only (`LSUIElement`, `.accessory` policy), no helper processes, no network listener, macOS 15 or later.

**Build (DEC-02).** A SwiftPM package with three targets: `MagpieLiteCore` (library, imports Foundation, Observation and CryptoKit (SHA-256) only — vault, tool adapters, parsers, switch, poller, app state, menubar summary), `MagpieLite` (executable — `@main` AppDelegate, status item, popover, manager window, login item; AppKit + SwiftUI), `MagpieLiteCoreTests` (Swift Testing). No target declares SwiftPM `resources:`; the Makefile assembles `build/MagpieLite.app` (`Contents/MacOS/MagpieLite`, `Contents/Resources/AppIcon.icns`, `Contents/Info.plist` from the checked-in template `Resources/Info.plist` with `LSUIElement`, `CFBundleDisplayName` "Magpie Lite", `LSMinimumSystemVersion` 15.0), signs it ad-hoc (`codesign --force --sign -`, overridable `SIGN=`), and `make install` copies it to `~/Applications/MagpieLite.app`, the only copy that is run or registered as a login item. Targets: `build`, `test`, `check` (build + test, the local pre-push gate), `install`, `run`, `clean` (R-25, C-01, C-02, C-05).
> **DEC-02** — SwiftPM package (core library importing only Foundation, Observation and CryptoKit + thin AppKit/SwiftUI executable + core test target) with a Makefile that assembles, plists, icons and ad-hoc signs `MagpieLite.app` and installs it to `~/Applications`; no SwiftPM resources. Binds: cross-cutting. Cites: R-25, C-01, C-02, C-05. ADR: none — follows the reference app's precedent and is reversible without data impact.

**Concurrency (DEC-08, ADR-0003).** `AppState` is `@MainActor @Observable` (accounts per tool, live identity per tool, latest reading per account, stale / needs-sign-in / app-needs-update / kept flags, refresh interval, Show-in-menubar choice per tool). `Poller` is `@MainActor` and loops `Task.sleep(for: interval)` → batch; one batch at a time; a fetch already queued or in flight for an account (batch or on demand) is joined, never duplicated. `Vault` is an `actor` owning the vault files and exposing `exclusive(tool:_:)`: a chained unstructured `Task` per tool inside which every vault write runs — renewal persist, switch, save, remove, undo, poll-time sync-back — so no two of them for one tool interleave across their awaits; each operation re-reads the state it decides on inside the section; the body runs to completion even if the caller is cancelled. Tool adapters are stateless `Sendable` structs. All `/usr/bin/security` calls go through one `nonisolated` async helper (terminationHandler set before `run()`, stdin closed after writing, pid watchdog kill after 20 s). HTTP requests time out after 15 s (R-25, R-26).
> **DEC-08** — `@MainActor @Observable` AppState and main-actor Poller (`Task.sleep` loop) that joins any queued or in-flight fetch of the same account; one `Vault` actor with a per-tool exclusive section implemented as a task chain that holds across awaits, inside which every vault write (renewal persist, switch, save, remove, undo, poll-time sync-back) runs and re-reads what it decides on; stateless `Sendable` tool adapters; renewal bodies in unstructured tasks; one `security` helper with a 20 s watchdog; 15 s HTTP timeouts. Binds: cross-cutting. Cites: R-25, R-26. ADR: 0003.

## 2. Tool contracts consumed (all `Fit: exact` — the tool or vendor owns the shape)

| Tool | Live login | Identity key | Renewal | Allowance |
|---|---|---|---|---|
| Claude Code | Keychain `Claude Code-credentials`/`$USER` (R-01) + `~/.claude.json` `oauthAccount` (R-02) | email (ci) + organizationUuid (R-02) | R-03 — refresh tokens single-use | R-04 `five_hour` / `seven_day` utilization 0–100; R-29 model-scoped weekly limits |
| Codex | `$CODEX_HOME/auth.json` (R-06); keyring/auto/ephemeral modes fail closed (PRD §Unsupported storage modes) | email (ci) + `chatgpt_account_id` (R-07) | R-08 by the app (DEC-03) | R-09 windows by `limit_window_seconds` |
| agy | Keychain `gemini`/`antigravity`, `go-keyring-base64:` envelope (R-11) + token file (R-11) + `modelProvider` absent (R-12) | id_token `sub` (R-11) | R-13 with the embedded Antigravity client (DEC-04); no rotation observed (R-13, R-22) | R-14 project → R-15 `5h` / `weekly` buckets per group |

Reading another tool's Keychain item uses `/usr/bin/security … -w`, stripping exactly one trailing newline (R-28); rc 44 = not found, any other failure or timeout = unknown. Writing it uses `security -i` with the command on stdin (R-16): the value goes as `-w` text when it holds only characters that need no quoting (agy's `go-keyring-base64:` envelope), else as `-X` hex (Claude's JSON); a command line over 4032 bytes (stdin's 4096-byte line buffer less headroom) falls back to the same command in argv, as claude-swap does. Today's items fit stdin: Claude 1431 bytes (hex 2862), agy 2223 bytes as text (R-28). Claude's live login spans two stores, so it is read as `~/.claude.json` → Keychain item → `~/.claude.json`; when the two `oauthAccount` reads differ the live state is unknown for that read. A failed read is unknown, never empty (PRD §Read failures).
> **DEC-12** — Keychain writes for another tool go through `security -i` on stdin with the value as plain `-w` text when no quoting is needed, else `-X` hex, and fall back to argv only when the command line exceeds 4032 bytes, accepting a momentary same-user process-list exposure over refusing the switch. Binds: F-03. Cites: R-16, R-28. ADR: none — one helper, reversible; owner-confirmed.

**Contexts (F-09, ADR-0004).** Claude Code and Codex can each run from another folder. In a Claude context, `CLAUDE_CONFIG_DIR=<P>` gives the Keychain item `Claude Code-credentials-<first 8 hex of sha256(NFC P)>` and the config `<P>/.claude.json` (`<P>/.config.json` the alternate), with the locks `<P>/.oauth_refresh.lock`, `realpath(P).lock` and `<config>.lock`. The variable unset is the default context: the plain item, `~/.claude.json` and `~/.claude.lock`. In a Codex context, `CODEX_HOME=<P>` holds `auth.json`, the keyring account hashed from its resolved path, and `app-server-daemon/daemon.pid`. agy has no folder setting. The Claude Keychain account is the login name when it is only letters, digits, `.`, `_` and `-`, else `claude-code-user`, as Claude Code 2.1.303 reads it.

## 3. Vault  (DEC-09 · ADR-0001)

Saved logins are owner-only files (PRD §Secrets): `~/Library/Application Support/MagpieLite/vault/<tool>/<id>.json`, 0600 files in 0700 folders, the vault folder marked excluded from backup on every launch. One file per account; `<id>` = SHA-256 hex of the canonical identity string (`claude:<email lowercased>:<organizationUuid>`, `codex:<email lowercased>:<chatgpt_account_id>`, `agy:<sub>`; incomplete identity → `<tool>:incomplete:<sha256(refresh token)>`). Envelope v1: `{v, tool, identity, identityKey, payload (base64 of the exact live bytes), generation, capturedAt, origin, kept, clientId?}`; Claude's `identity` keeps the whole `oauthAccount` object, which a switch writes back. Save, like every vault write, runs in the tool's exclusive section. Write: staged `O_EXCL` 0600 temp in the same folder → `F_FULLFSYNC` → clone current file to `.prev` → `rename(2)`; on launch a stray temp with a higher generation than its target is promoted, else deleted. Load validation (parse, `v == 1`, tool matches folder, hash matches name, payload decodes) failing → unreadable vault entry; the write path refuses that id. `.prev` is never restored automatically. Remove runs in the tool's exclusive section: it captures the entry's raw file bytes (after every earlier queued operation of that tool — renewal, switch, Save, poll-time sync-back — has persisted), then deletes the file and `.prev`; the bytes stay in memory only while the Undo banner is shown. Undo, also in the section, writes those raw bytes back through the staged write only when no entry with that id exists — a newer entry (e.g. a removed live account kept again by a switch, DEC-05) always wins. A non-blocking exclusive `flock` on `vault/.lock`, held for the process lifetime, keeps one instance. Allowance readings stay in memory (R-24, R-20).
> **DEC-09** — one owner-only JSON envelope per account at `vault/<tool>/<sha256(identityKey)>.json` holding base64 of the exact live credential bytes; staged O_EXCL 0600 + F_FULLFSYNC + `.prev` clone + rename; invalid files are unknown and never written over; `.prev` forensic only; launch-lifetime `flock` single instance; backup exclusion re-applied each launch; readings never stored in the vault. Binds: F-02, F-03, F-04, F-07. Cites: R-24, R-20. ADR: 0001.

## 4. Switch transaction  (DEC-05 · DEC-06)

System-wide in-place swap of the tool's live login (PRD §Switch). Inside `Vault.exclusive(tool)`; for Claude, Claude Code's lock directories (R-05) are held from step 2 through step 5 including any rollback, which do no network, so a renewal by Claude Code cannot land between the outgoing read and the target write; a lock Claude Code holds is waited on within its retry budget and broken only past R-05's stale ages, otherwise the switch is refused with the retry notice and nothing is written:
1. Target equals the live identity → no write.
2. Re-read the live login (R-28 / R-06; Claude as the §2 pair read) and the target entry. Unreadable or unknown → refuse; nothing written.
3. Classify the outgoing login (DEC-05): identity matches a saved account → overwrite that entry with the live bytes, keeping its `kept` flag (sync-back); valid but unsaved → save as a new entry with `kept: true`; incomplete identity → its own `incomplete` entry, never merged; wiped (item or file present, token fields empty) or absent → store nothing.
4. Snapshot every store the write will touch, then write the target:
   - **Claude** — under the locks taken at step 2: Keychain item via `security -i` with the target's one-line JSON, where the live values of `mcpOAuth`, `mcpOAuthClientConfig`, `mcpXaaIdp`, `mcpXaaIdpConfig`, `pluginSecrets` are kept (R-01); then `~/.claude.json` with only `oauthAccount` replaced, atomic write (R-02). An existing `~/.claude/.credentials.json` gets the same value so running sessions see its mtime change; it is never created, and a failure there does not fail the switch.
   - **Codex** — target bytes to `$CODEX_HOME/auth.json` via staged 0600 file + fsync + rename (R-20).
   - **agy** (DEC-06) — Keychain `gemini`/`antigravity` via `security -i` with the target envelope, the token file `~/.gemini/antigravity-cli/antigravity-oauth-token` (0600, temp + rename), and `modelProvider` removed from agy's `settings.json`, other keys untouched (R-11, R-12, R-16).
5. Verify by re-reading every written store and checking the identity read back is the target (Claude: the Keychain bytes read back equal the bytes written and `oauthAccount` equals the target's); any write or verify failure restores every live-store snapshot (an absent-before file is removed) and reports failure. The vault write of step 3 stands: it holds the freshest copy of the outgoing login, and restoring an older one could resurrect a spent refresh token (ADR-0001).
6. Pick-up notice (PRD §Post-switch pick-up): Claude — new sessions now, running ones within ~30 s; Codex — a running managed app-server is restarted at once so attached sessions move over (running turns get Codex's drain, up to a minute by default), with Restart to retry on failure; a running Codex desktop app still uses the previous account (R-10, R-20); agy — next session.
> **DEC-05** — an unsaved outgoing live login is saved automatically as a vault account flagged `kept` (badge "kept", cleared when the owner presses Save on it while it is live); a wiped or absent outgoing login stores nothing; an unreadable one aborts the switch; an incomplete identity becomes its own entry keyed by its refresh-token fingerprint and never matches a complete identity. Binds: F-01, F-03. Cites: R-01, R-06, R-11. ADR: none — reversible behaviour, no persisted-format impact beyond the `kept` flag.
> **DEC-06** — an agy switch writes the Keychain item, the token file and the `modelProvider` removal as one transaction with snapshot rollback, captures the outgoing login from the Keychain (the freshest copy), and verifies by reading the Keychain back through `security`. Binds: F-03. Cites: R-11, R-12, R-16. ADR: none — reversible; a Keychain-only write would leave SSH sessions (which read the file) on the old account.

## 5. Allowance and renewal  (DEC-03 · DEC-04 · DEC-07 · ADR-0002)

Interval 3 / 5 / 10 min (default 5, persisted), each sleep a random ±10% of it so batches keep no fixed beat; one batch at launch and at each interval of every pollable saved account (not needs sign-in, app needs update, incomplete or unreadable) plus each tool's live login read-only, whether saved or not (a saved live account is fetched once, through its live token); on demand, "Refresh live accounts" fetches each tool's live account now and an account row's refresh fetches that account now (PRD §Freshness). A batch fetches sequentially, and every usage request to one vendor (batch or on demand) waits for the previous one to finish plus a random 3–10 s; a fetch of an account whose fetch is already queued or in flight joins it (FR-04.21). On-demand fetches obey the same 429 backoff and 60 s Codex reuse as the batch.

**Renewal ownership** (PRD §Login renewal ownership). The tool renews its live account; the app renews only saved, non-live accounts, and only when the stored access token expires within 5 minutes or the allowance fetch returned 401. Renewal runs in `Vault.exclusive(tool)`: re-read the live identity and the stored entry; skip if the tool's live state is unknown, unsupported or incomplete (the account might be live), if the entry is gone, live or incomplete, or its stored access token is no longer the one that expired or drew the 401 (an earlier operation renewed or synced it); else send the refresh request (awaited to completion), merge the reply into the stored payload (unknown keys kept), persist (DEC-09), then fetch. Claude: R-03. Codex: R-08 (DEC-03). agy: R-13 with the embedded client (DEC-04); a `refresh_token` in Google's reply is persisted if present (R-22). Refused renewal (Claude 4xx with `invalid_grant`, R-03; Codex 400 or 401 whatever the body, ADR-0002, R-08; Google 400 `invalid_grant`) → needs sign-in, vault untouched, no retry. Any other non-2xx reply (not refused, not Google `invalid_client`), timeout or network error → transient, stale reading, retried next cycle. Google 400 or 401 `invalid_client`, or a saved agy login whose recorded `clientId` differs from the embedded client → "app needs update" for every account of that client, no renewal request for that client until relaunch (live-token allowance fetches continue). Any write of live bytes into an entry (Save or sync-back) clears needs sign-in; it clears app needs update only when the written login's `clientId` has an embedded client that has not drawn `invalid_client` since launch. Incomplete entries are kept but never renewed, fetched or switched to.

**Poll-time sync-back** (PRD §Sync-back). When a live read in a batch or a live refresh yields a complete identity that matches a saved entry whose payload differs from the live bytes, a sync-back is queued in the tool's exclusive section. Inside it the live login and the entry are re-read, and the live bytes are written, keeping the re-read entry's `kept` flag, only when the entry still exists and is readable, the re-read live identity still equals it, and the re-read live bytes still differ from its payload; otherwise nothing is written. For Claude, whose login spans two stores the tool does not write together, a sync-back is queued only from an interval batch's live read, and the in-section pair read must also equal the pair read by the previous interval batch (two consecutive batches agreeing; on-demand refreshes fetch allowance but neither queue a Claude sync-back nor move that baseline), so a half-finished sign-in is never copied. Unknown, unsupported or incomplete live states never sync back. A Claude switch composes the Keychain JSON, so the second batch after it usually syncs back once (the first compares against the pre-switch read); that write is expected.

**Live-account allowance** uses the tool's current access token read from its live store; the app never renews it (agy alone: an expired live token is replaced in memory, FR-04.13); an expired token leaves the last reading, marked stale. The token and the identity its reading is attributed to come from one read of the live store, and readings are keyed by identity, so a switch during the request cannot misattribute it.

**Requests.** Claude: `GET https://api.anthropic.com/api/oauth/usage`, `Authorization: Bearer`, `anthropic-beta: oauth-2025-04-20`, `User-Agent: magpie-lite/<version>` (DEC-07) (R-04). Codex: `GET https://chatgpt.com/backend-api/wham/usage`, Bearer + `chatgpt-account-id`, readings reused for 60 s (R-09). agy: `loadCodeAssist` on the prod host for the project (kept in memory per account), `retrieveUserQuotaSummary` on the daily host, `User-Agent: antigravity/cli/1.4.0 darwin/arm64` (R-14, R-15, R-22).

**Readings.** A reading is a list of groups, each with a name, an optional 5 h window and an optional 7 d window (remaining %, reset time). Claude: group "All models" from `five_hour` / `seven_day`, then one weekly-only group per model-scoped weekly limit in `limits[]` (`kind` `weekly_scoped`, `group` `weekly`, named by `scope.model.display_name`; an "all models" scope skipped; duplicates collapse by model id, else name; remaining = 100 − `percent`) (R-29); legacy `seven_day_opus` / `seven_day_sonnet` keys are ignored. Codex: one unnamed group. agy: one group per vendor group, named by its `displayName`.

**Parsing.** Windows are identified by duration — Claude `five_hour`/`seven_day`; Codex `limit_window_seconds` 18000 / 604800 regardless of primary/secondary; agy bucket `window` `5h`/`weekly` and the aliases in R-22. Remaining = 100 − utilization (Claude), 100 − used_percent (Codex), remainingFraction × 100 with a missing fraction read as 0 and disabled buckets skipped (agy). A window not returned shows "—".

**Rate limits and staleness.** A 429 backs off that account only (vendors budget per account — Claude ~28–30 usage requests per sliding hour per account/org, shared by every client holding its tokens, refs/claude-swap poll_policy.py) per FR-04.5; any non-200 keeps the last good reading with a stale marker and its age; a non-200 Claude response's status and body are kept for the account's error detail (R-04, R-19, R-26).
> **DEC-03** — saved Codex accounts are renewed by the app with the OAuth refresh grant over HTTP, inside the Codex exclusive section, awaited and persisted before use; renewal only near access-token expiry or after a 401; never CLI-delegated. Binds: F-04. Cites: R-08, R-21. ADR: 0002.
> **DEC-04** — the Antigravity OAuth client id and secret are embedded constants in one source file keyed by client id; every saved agy login records its id_token `azp` as `clientId`; a missing entry or Google `invalid_client` marks the account "app needs update" instead of needs sign-in. Binds: F-02, F-04. Cites: R-13, R-22. ADR: none — reversible, one constant.
> **DEC-07** — Claude allowance requests send the honest constant `User-Agent: magpie-lite/<version>` and never fall back to the Claude CLI's UA automatically; any non-200 is surfaced with its status. Binds: F-04. Cites: R-04, R-19. ADR: none — one string, reversible.

## 6. Presentation  (DEC-01 · DEC-10 · DEC-11)

`@main` AppDelegate sets `.accessory` policy, installs a minimal app menu (Quit, Close, Copy, Paste), and creates the status item. Clicking it toggles one `NSPopover` (`.transient`, `NSHostingController` with `.preferredContentSize`), shown after `NSApp.activate()`; when the item has no window (menubar overflow) programmatic open falls back to the manager window. Popover rows have fixed heights; no `.compositingGroup`/`.blendMode` (R-18). The manager window is an `NSWindow` hosting SwiftUI; while it is open the policy is `.regular`, back to `.accessory` on close. Launch at login: `SMAppService.mainApp` register/unregister with status check (R-23). Popover and manager follow the system light or dark appearance.
> **DEC-01** — AppKit `NSStatusItem` plus one transient `NSPopover` hosting SwiftUI, and an `NSWindow` hosting the SwiftUI manager; no `MenuBarExtra`, no `NSMenu`-hosted cards. Binds: F-05, F-06, F-07. Cites: R-17, R-18, R-27. ADR: none — the shell can be swapped without data impact.

**Status item (DEC-10).** `NSStatusItem.variableLength`; `button.image` is one non-template image, `imagePosition = .imageOnly`, rebuilt whenever the core's menubar summary, a Show-in-menubar choice, or the button's `effectiveAppearance` changes. One segment per shown tool that has a live login, in the order Claude, Codex, agy: a 14 × 14 pt rounded square (radius 4, 1.5 pt stroke) holding the tool letter (C / X / G, 8.5 pt heavy), a 4 pt gap, then two right-aligned rows — 5 h on top, 7 d below — reading `NN%` or `—` in the 9.5 pt semibold monospaced-digit system font on a 10 pt line (two rows fit the 22 pt button, R-30); segments 10 pt apart, 8 pt side padding. Colours resolve against the button's appearance: foreground `labelColor`; a value under 15 in `barLow`; a tool whose live reading is stale has its segment drawn at 70 % opacity in `secondaryLabelColor`, values under 15 staying `barLow`. No segment → the template app glyph (three rising bars) — the one template image. The button's accessibility label speaks each segment ("Claude Code 5 h 62%, 7 d 40%; Codex 5 h 80%, 7 d 71%"), or "Magpie Lite" with no segment. Each tool's Show-in-menubar choice lives in `UserDefaults`, on by default (R-17, R-30, C-06).
> **DEC-10** — the status item draws its content as one non-template image rebuilt on summary, visibility or appearance change: per shown tool with a live login the tool's own icon (its white silhouette tinted to the menubar text colour; an outlined letter mark if the icon file is missing) with its 5 h value over its 7 d value (the share used, highest across the live account's groups), red over 85, a stale tool's segment drawn like a fresh one, the template app glyph alone when no segment remains; a per-tool Show-in-menubar choice persisted in `UserDefaults`, on by default. Binds: F-05, F-07. Cites: R-17, R-30, C-06. ADR: none — presentation only, swappable without data impact.

## Glossary
- **Live login** — the credential a tool uses for its next session, in the tool's own store. _Avoid_: active token, current session.
- **Saved login / vault** — the app's owner-only copy of a login, one envelope file per identity (ADR-0001). _Avoid_: profile, slot, backup.
- **Sync-back** — overwriting a vault entry with the tool's current live bytes: before switching away (§4) and on any poll that finds them changed (§5). _Avoid_: backup, harvest.
- **Kept account** — a vault entry created automatically from an unsaved outgoing live login, flagged `kept` until the owner saves it (DEC-05). _Avoid_: stash, unclaimed.
- **Renewal** — exchanging a refresh token for new tokens with the OAuth `refresh_token` grant. _Avoid_: refresh (ambiguous with allowance refresh).
- **Exclusive section** — the per-tool task chain in `Vault` inside which every vault write for that tool — renewal, switch, Save, Remove, Undo, poll-time sync-back — runs to completion (ADR-0003). _Avoid_: lock, mutex.
- **Window** — an allowance period identified by its duration: 5 h (300 min) or 7 d (10080 min). _Avoid_: primary/secondary.
- **App needs update** — the state of an agy account whose OAuth client is not embedded in the app or drew Google `invalid_client` (DEC-04). _Avoid_: expired.
- **Group** — one set of allowance windows within an account's reading: Claude "All models" plus one weekly-only group per model-scoped limit; agy's vendor groups; Codex's single unnamed group (§5). _Avoid_: bucket, lane.
- **Shown tool** — a tool whose Show-in-menubar choice is on (DEC-10). _Avoid_: enabled, active.
- **Running-low suggestion** — the live-row prompt to switch to a fresh saved account with headroom (FR-06.6). _Avoid_: alert, notification, auto-switch.
- **Context** — one folder a tool runs from, named by its variable's exact value (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`); the default is the variable unset. Accounts are shared by every context (ADR-0004). _Avoid_: profile, environment, workspace.
