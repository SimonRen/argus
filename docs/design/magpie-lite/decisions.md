# Decisions — magpie-lite   compiled from tech-design.md @ round 13

| DEC | Shape (verbatim) | Section | Cites | Binds | ADR |
|---|---|---|---|---|---|
| DEC-02 | SwiftPM package (Foundation-only core library + thin AppKit/SwiftUI executable + core test target) with a Makefile that assembles, plists, icons and ad-hoc signs `MagpieLite.app` and installs it to `~/Applications`; no SwiftPM resources | §1 | R-25, C-01, C-02, C-05 | cross-cutting | none — follows the reference app's precedent and is reversible without data impact |
| DEC-08 | `@MainActor @Observable` AppState and main-actor Poller (`Task.sleep` loop) that joins any queued or in-flight fetch of the same account; one `Vault` actor with a per-tool exclusive section implemented as a task chain that holds across awaits, inside which every vault write (renewal persist, switch, save, remove, undo, poll-time sync-back) runs and re-reads what it decides on; stateless `Sendable` tool adapters; renewal bodies in unstructured tasks; one `security` helper with a 20 s watchdog; 15 s HTTP timeouts | §1 | R-25, R-26 | cross-cutting | 0003 |
| DEC-12 | Keychain writes for another tool go through `security -i` on stdin with the value as plain `-w` text when no quoting is needed, else `-X` hex, and fall back to argv only when the command line exceeds 4032 bytes, accepting a momentary same-user process-list exposure over refusing the switch | §2 | R-16, R-28 | F-03 | none — one helper, reversible; owner-confirmed |
| DEC-09 | one owner-only JSON envelope per account at `vault/<tool>/<sha256(identityKey)>.json` holding base64 of the exact live credential bytes; staged O_EXCL 0600 + F_FULLFSYNC + `.prev` clone + rename; invalid files are unknown and never written over; `.prev` forensic only; launch-lifetime `flock` single instance; backup exclusion re-applied each launch; readings never stored in the vault | §3 | R-24, R-20 | F-02, F-03, F-04, F-07 | 0001 |
| DEC-05 | an unsaved outgoing live login is saved automatically as a vault account flagged `kept` (badge "kept", cleared when the owner presses Save on it while it is live); a wiped or absent outgoing login stores nothing; an unreadable one aborts the switch; an incomplete identity becomes its own entry keyed by its refresh-token fingerprint and never matches a complete identity | §4 | R-01, R-06, R-11 | F-01, F-03 | none — reversible behaviour, no persisted-format impact beyond the `kept` flag |
| DEC-06 | an agy switch writes the Keychain item, the token file and the `modelProvider` removal as one transaction with snapshot rollback, captures the outgoing login from the Keychain (the freshest copy), and verifies by reading the Keychain back through `security` | §4 | R-11, R-12, R-16 | F-03 | none — reversible; a Keychain-only write would leave SSH sessions (which read the file) on the old account |
| DEC-03 | saved Codex accounts are renewed by the app with the OAuth refresh grant over HTTP, inside the Codex exclusive section, awaited and persisted before use; renewal only near access-token expiry or after a 401; never CLI-delegated | §5 | R-08, R-21 | F-04 | 0002 |
| DEC-04 | the Antigravity OAuth client id and secret are embedded constants in one source file keyed by client id; every saved agy login records its id_token `azp` as `clientId`; a missing entry or Google `invalid_client` marks the account "app needs update" instead of needs sign-in | §5 | R-13, R-22 | F-02, F-04 | none — reversible, one constant |
| DEC-07 | Claude allowance requests send the honest constant `User-Agent: magpie-lite/<version>` and never fall back to the Claude CLI's UA automatically; any non-200 is surfaced with its status | §5 | R-04, R-19 | F-04 | none — one string, reversible |
| DEC-01 | AppKit `NSStatusItem` plus one transient `NSPopover` hosting SwiftUI, and an `NSWindow` hosting the SwiftUI manager; no `MenuBarExtra`, no `NSMenu`-hosted cards | §6 | R-17, R-18, R-27 | F-05, F-06, F-07 | none — the shell can be swapped without data impact |
| DEC-10 | the status item draws its content as one non-template image rebuilt on summary, visibility or appearance change: per shown tool with a live login an outlined letter mark with its 5 h value over its 7 d value (lowest across the live account's groups), red under 15, a stale tool's segment dimmed, the template app glyph alone when no segment remains; a per-tool Show-in-menubar choice persisted in `UserDefaults`, on by default | §6 | R-17, R-30, C-06 | F-05, F-07 | none — presentation only, swappable without data impact |
| DEC-11 | the owner-approved design snapshot in `ui/` is the visual source of truth for tokens, layout and copy, the pack winning on conflict: popover collapsed to each tool's live account with "+N more", uniform rows with per-group 5 h and 7 d bars coloured ok at 40 or more, warn at 15 or more, low under 15, per-row refresh and a running-low suggestion on the live row; sidebar-plus-detail manager with Show in menubar and remove with Undo; light and dark tokens | §6 | C-06, R-18 | F-05, F-06, F-07 | none — presentation only, no data impact |
